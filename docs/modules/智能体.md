## 字段合同

### TripRequest

由 A 提取/校验，B 天气与规则消费，C 在会话中保存并传回下一轮。数值严格接受 Python int，拒绝 bool、浮点数、数字字符串。默认值用于演示，是否经用户确认以 assumed_fields 为准。

| 字段 | 类型 | 默认/空值 | 产生/消费 | 异常处理 | 示例 |
|---|---|---|---|---|---|
| city | str | 成都 | A → B/C | 空值、非字符串或超过80字符拒绝 | 成都 |
| start_date | str | 空字符串：未给日期 | A → B/C | 非 YYYY-MM-DD、无效日期拒绝；本地提取保留上次可靠日期并提示 | 2026-10-28 |
| days | int | 3 | A → B/C | 1—7；越界提示并回退，不静默裁剪 | 3 |
| budget | int | 3000 | A → B/C | 0—100000；0是有效的用户预算；负数拒绝 | 2500 |
| adults | int | 1 | A → B/C | 0—10；合计至少1人 | 1 |
| elderly | int | 1 | A → B/C | 同上；默认1不等于用户确认 | 1 |
| children | int | 0 | A → B/C | 同上 | 0 |
| pace | str | 舒缓 | A → B/C | 仅舒缓/适中/紧凑 | 舒缓 |
| rain_days | list[int] | [] | A → B/C | 用户模拟条件；1—days，去重排序；缩短行程时移除超出的旧雨天 | [2] |
| preferences | list[str] | [] | A → B/C | 最多30条，每条1—100字符，去重；错误类型拒绝 | ["少走路"] |
| origin | str | 空字符串：未给出发地 | A → B/C | 非字符串或超过80字符拒绝 | 北京 |
| assumed_fields | list[str] | city/days/budget/adults/elderly/children/pace | A → C/下一轮A | 只允许请求业务字段名；用户显式赋值后移出 | ["adults","children"] |

travelers 是计算属性，值为 adults + elderly + children（校验后至少1）。to_dict() 不额外序列化该属性。normalized() 返回独立副本，调用方应写 request = request.normalized()；错误模型数据不自动转换成看似正确的数据。

### WeatherContext

| 字段 | 类型 | 默认/空值 | 产生/消费 | 异常处理 | 示例 |
|---|---|---|---|---|---|
| status | str | 必填 | B provider → A/B规则/C | 仅允许下列状态；未知值由 A 转 error | no_date |
| summary | str | 必填 | B → A/C | 类型异常转 error，不暴露原始异常正文 | 尚未提供出发日期 |
| daily | list[dict] | [] | B → A/B规则/C | ok 要有 days 条连续日期；不足转 incomplete，坏日期/概率转 error；失败状态清空 daily | [{"date":"2026-10-28","rain_probability":80}] |
| source | str | Open-Meteo | B → A/C | 关闭或异常为 none；测试替身为 test-double | Open-Meteo |

天气状态：ok、no_date、past、out_of_range、city_not_found、incomplete、error、disabled。逐日 date 为 ISO 日期，rain_probability 为 0—100 的有限数值或 None；B 还可提供 weather_code、max_c、min_c。A 不自行预测天气，不把用户 rain_days 写进真实天气结果。

### AgentResponse

| 字段 | 类型 | 默认/空值 | 产生/消费 | 异常处理 | 示例 |
|---|---|---|---|---|---|
| request | TripRequest | 必填 | A → C/下一轮A | 调用方 previous 不合法则抛 ValueError，不静默污染历史 | 见上表 |
| weather | WeatherContext | 必填 | B/A → C | 天气失败保留状态和说明 | status=error |
| itinerary | list[dict] | 非成都也可有方向性建议 | B或A → C | 非成都活动 price_per_person=None、地点未核实 | 第2天室内安排 |
| budget_items | list[dict] | 未核实为 [] | B → A/C | 类别category、整数amount、说明detail；总额不一致则隐藏结论 | 住宿1240 |
| total_cost | int | 未核实占位0 | B → A/C | 0不能解释为零成本；以 budget_status 为准 | 2790 |
| within_budget | bool | 未核实为False | A → C | 仅 estimated 状态才有比较意义 | True |
| changes | list[str] | [] | B → A/C | 不把仅记录偏好写成已优化路线 | 第2天室内替换 |
| warnings | list[str] | [] | B/A → C | 含默认未确认、降级和模块限制 | 预算未核实 |
| booking_tasks | list[dict[str,str]] | 4项人工待办 | A → C | 无日期时 due 为待确定出发日期/出发前 | task/due/status |
| trace | list[dict[str,str]] | 每轮生成 | A → C | 每项step/detail，展示当前流程与回退 | 天气工具：error |
| coverage | str | 必填 | A → C | 成都标教学估算；非成都标未核实 | 成都样例数据 |
| answer | str | 必填 | A → C | 失败不宣称真实接口成功或预算符合 | 估算¥2790 |
| budget_status | str | unverified（旧构造安全默认） | A → C | estimated_within_budget / estimated_over_budget / unverified | estimated_within_budget |
| extraction_status | str | 空字符串（旧构造默认） | A → C | 描述本地、模型、回退原因；不含密钥 | 已回退本地提取 |
| schema_version | str | 1.0 | A → C | 以合同v1解释新增字段 | 1.0 |

itinerary 每天有 day、date、rainy、rain_source、activities、note；活动至少含 name、indoor、price_per_person。rain_source 为演示模拟/实时预报/空字符串。真实预报与模拟必须分开标记；离线天气成功证据的 source=test-double，不能声称实际联网。

脱敏的完整响应均来自实测：docs/evidence/agent-demo.json。rounds[0].response 为基础成都，rounds[1].response 为雨天；scenarios.bad_json.response 为模型坏JSON回退；scenarios.non_chengdu.response 为未知报价。该文件包含 request、天气、行程、全部分项、警告、待办和轨迹，无密钥。

## 流程及失败分支

1. C 传入本轮文字和上一轮 result.request；A 从独立副本开始，历史列表不会被新一轮修改。
2. 本地提取可靠字段，保留未修改条件；显式字段移出 assumed_fields。错误日期、越界数值提示并保留可靠值。
3. 可选模型仅返回 updates 增量及 generic_ideas。严格验证JSON对象、键、类型、范围；本地明确字段优先。模型通用自由文本不进入非成都行程，避免把未经核实价格或天气当作事实。
4. 调用 B 天气 provider，传入请求副本。A 验证返回对象、状态、日期完整性和概率。失败不捏造预报。
5. 成都调用 B 的 build_chengdu_plan(request, weather)；价格表、方案和公式仍在 B。非成都给明确未核实的通用室内方向。
6. A 核对费用分项之和与 B 总额一致，生成 budget_status、默认值/降级警告、人工待办和 trace。
7. C 消费 AgentResponse 并保留完整字段，下一轮继续传入 request。

| 分支 | 实际行为 | 用户可见内容 | 证据/状态 |
|---|---|---|---|

## 已知限制与给 C/文斓的交接
