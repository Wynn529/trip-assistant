## 职责边界

A负责需求提取、状态合并、合同校验、编排与回退；规则、天气、城市数据由团队提供相应依赖，页面和存储由C消费输出。本文描述当前集成后的行为；其中 C 补充的城市目录、规划规则及口语提取增强按源码注释标明来源，不把这些改动全部归为 A 独立完成。

主责源码：travel_agent/contracts.py、llm.py、service.py；__init__.py沿用前期导出入口。tests/test_agent.py用于A验收，demo_agent.py与run_agent_checks.py用于演示和证据。

## 字段合同

TripRequest由A提取并保存，供规划、天气与下一轮使用。默认值是演示假设，未确认字段以assumed_fields标识。

| 字段 | 类型 | 默认/空值与约束 |
|---|---|---|
| city | str | 成都；非空，最多80字符 |
| start_date | str | 空字符串为未提供；非空必须是有效YYYY-MM-DD |
| days | int | 3；1—7 |
| budget | int | 3000；0—100000，0为有效用户预算 |
| adults | int | 1；0—10 |
| elderly | int | 1；0—10 |
| children | int | 0；0—10；三类人数合计至少1 |
| pace | str | 舒缓；仅舒缓/适中/紧凑 |
| rain_days | list[int] | []；模拟雨天天数去重排序；缩短行程移除超出的旧条件 |
| preferences | list[str] | []；最多30条，每条1—100字符，去重 |
| origin | str | 空字符串为未提供，最多80字符 |
| assumed_fields | list[str] | 默认城市/天数/预算/三类人数/节奏；明确给值后移出 |

严格拒绝数字字符串、bool、小数冒充int。normalized()校验并返回独立副本，不修改历史；travellers数量实际属性名为travelers，值来自三类人数之和，未额外序列化。

WeatherContext由天气依赖返回，A校验后供规则与页面使用：

| 字段 | 类型 | 约束/失败 |
|---|---|---|
| status | str | ok/no_date/past/out_of_range/city_not_found/incomplete/error/disabled |
| summary | str | 用户可见说明，不含原始异常正文或密钥 |
| daily | list[dict] | 默认[]；ok需days条连续date，匹配出发日期；概率为0—100有限数值或None |
| source | str | 默认Open-Meteo；关闭/异常为none，测试替身明确test-double |

失败状态清空daily，不把用户模拟条件当作真实预报。注入provider收到的是请求副本，不能污染后续会话状态。

AgentResponse由A整合返回，C直接消费：

| 字段 | 类型 | 含义/空值 |
|---|---|---|
| request | TripRequest | 本轮完整状态，传给下一轮 |
| weather | WeatherContext | 查询状态、解释与逐日结果 |
| itinerary | list[dict] | day/date/rainy/rain_source/activities/note |
| budget_items | list[dict] | category/amount/detail；未核实为[] |
| total_cost | int | 已知估算；未核实保留兼容占位0 |
| within_budget | bool | 已知估算与用户预算比较；未核实为False |
| changes | list[str] | 规则实际返回的调整，不虚构已优化 |
| warnings | list[str] | 规则限制、默认未确认、输入/工具失败等 |
| booking_tasks | list[dict] | 4项人工待办，含task/due/status；无日期明确待定 |
| trace | list[dict] | step/detail，含提取、记忆、天气、规则/覆盖、预算和输出 |
| coverage | str | 教学估算/未核实覆盖说明 |
| answer | str | 简明结果和预算结论 |
| budget_status | str | estimated_within_budget / estimated_over_budget / unverified |
| extraction_status | str | 本地/模型/回退/未提及字段忽略说明 |
| schema_version | str | 1.0 |

活动至少含name、indoor、price_per_person；已收录城市使用当地样例单价，未收录城市的方向性活动为price_per_person=None。C必须先判断budget_status，不能用0推导免费或预算余额；保存完整to_dict结果，不遗漏新增字段。已收录仅表示具有课程样例数据，不表示报价经过实时核验。

## 当前提取能力与模型配置（llm.py）

每轮先运行本地提取。关闭模型或没有密钥时直接使用本地结果；启用模型且有密钥时，再请求结构化增量，并以本地已明确提取的字段为准。不是让模型直接生成并覆盖整个行程。

| 输入或配置 | 当前行为 | 实现与边界 |
|---|---|---|
| “成都，4天”“上海4天，3人” | 单一常见城市即使没有“去”也可被本地识别 | `KNOWN_CITIES` 是提取词表；不等于具备预算数据的城市列表。多个候选城市时提示用户明确目的地；匹配到的“某地出发”不作为目的地兜底 |
| “预算两千五”“预算一万二”“预算三百五” | 本地分别按2500、12000、350元处理 | `_chinese_number` 支持省略末位单位的常见写法；不保证所有中文数词或混合记法均能理解 |
| “2500元” | 本轮只有一个金额且不含单价提示时，可作为总预算 | 含每人、人均、每晚、一晚、每天、门票、单价等提示时，不走此兜底；仍有上下文误判可能 |
| “我自己一个人”“两个人”“3人” | 没有明确分组人数时，按全部为成人，老人和儿童置0 | 成人仍受0—10限制；越界保留可靠原值并给提示 |
| “两个大人”“一个孩子” | 本地明确成人或儿童，且未提老人、旧老人数仍是默认假设时，老人数改为0 | 已经由用户确认的老人数保留；避免演示默认老人被当成真实同行者 |
| “爸妈”“老婆带个娃”“别太累”“后天”“国庆” | 扩展模型字段提及词表，允许相应人数、节奏、日期增量进入校验 | 此词表只是准入条件；本地规则不会完整理解这些口语或相对日期。离线替身测试验证的是给定增量如何合并，真实模型理解仍需实测 |
| 模型设置 | 读项目根目录`.env`及环境变量；默认模型`deepseek-flash`，默认地址`https://api.deepseek.com` | `DEEPSEEK_MODEL`、`DEEPSEEK_BASE_URL`可覆盖；`.env`通过`setdefault`加载，不覆盖已有环境变量 |
| 请求参数 | JSON对象输出、temperature=0、max_tokens=700、thinking disabled | 请求携带当天日期、previous和本轮文字；这些参数不构成语义正确性保证 |

## 城市覆盖与预算分支（service.py）

当前样例库收录 **成都、北京、上海、广州、重庆、西安**。`find_city`按名称或已登记别名查找并返回副本；提取器能识别杭州等更多城市，但这些城市尚无本地预算样例。

| 分支 | 编排接口 | 预算与输出 |
|---|---|---|
| 成都 | `build_chengdu_plan(request, weather)` | 沿用成都配置，返回行程、费用分项、总额、调整和警告 |
| 其他已收录城市 | `build_city_plan(request, weather, city_data)` | 使用当地样例日程、活动、酒店和单价；覆盖说明标明城市及“演示估算” |
| 未收录城市（如杭州） | 不调用城市规划规则 | 返回待核实的通用室内活动方向；分项=[]、total_cost=0、within_budget=False、budget_status=unverified；0只是兼容占位 |
| 已收录但费用无效 | 校验分项与总额后降级 | 总额须为非负整数、分项非空且amount均为非负整数、分项之和等于总额；失败时清空费用，标为unverified并提示核对 |

已收录城市中，`estimated_within_budget`只表示样例估算不超过用户预算；`estimated_over_budget`表示规则调整后仍超预算。当前团队规则会尝试经济档及较便宜的活动；这是一套启发式调整，不是全局最低成本的数学证明。A保留规则返回的实际changes/warnings，不伪造优化成功。

“少走路”会进入规划规则；当前团队实现对一天超过一个主要活动的情况保留时长较短的一项，并记录删减原因。未收录城市仅保留偏好和方向性建议。该功能不测量真实步行距离，也不保证路线无障碍。预算仅含规则列出的样例费用，往返大交通报价尚未接入。

## 多轮与失败流程

1. 从previous或演示默认值的独立副本开始，提取本轮明确变动。
2. 可选模型返回updates增量；先校验JSON形状、键、类型、范围，再忽略本轮未涉及的字段。本地明确值优先。
3. 调用天气依赖，异常转换为error，坏日期或概率不进入行程判断。
4. 查询城市目录：成都调用build_chengdu_plan，其他已收录城市调用build_city_plan，均返回五项；未收录城市才返回未核实方向。
5. 校验费用分项与总额一致，输出预算状态，保留规则changes/warnings，生成待办与轨迹。

无Key使用本地提取；模型超时/坏JSON/坏字段最多尝试2次后回退。错误本地日期或越界数值保留可靠原值并提示。无日期/超预报范围不编造预报。调用方previous损坏抛清楚的ValueError，便于页面重置。

少走路的效果以实际活动和规则说明为准。其他已收录城市的轨迹写明本地城市数据；未收录城市不声称执行了成都规则。预算下调后已可负担的同一方案可保留，但仍重新调用规则并核对总额。

## 现有防御措施与局限

这些措施依据当前源码，不表示已经通过专门的对抗攻击评估。

| 风险 | 已有措施 | 尚存边界 |
|---|---|---|
| 用户文字包含“忽略系统规则”等指令 | 模型system消息明确用户文字是待解析数据；用户内容与previous以JSON放入独立user消息 | 提示约束不能保证完全抵御提示注入；当前没有专门攻击集及防御成功率数据 |
| 模型输出任意字段或坏类型 | 只接受updates/generic_ideas信封；updates只允许REQUEST_FIELDS；合并前检查类型、日期、数值范围和列表形状，拒绝bool/小数冒充整数 | 结构合法仍可能语义错误；校验不能代替用户确认 |
| 模型用旧默认值重置多轮条件 | `_field_mentioned`过滤本轮未涉及字段，本地explicit值优先；默认值仍由assumed_fields标识 | 提及检查依赖词表，是启发式。明确成人或儿童且老人数仍未确认时，另有接受模型老人字段的例外；不能笼统声称“未提及字段绝不改变” |
| 模型自由文本冒充价格、天气或操作命令 | 解析器最多返回3条、每条最多100字符的generic_ideas；`TravelAgent.turn`将它们接收为`_ideas`，当前不用于行程、报价或天气；模型输出不作为可执行代码运行 | 模型仍可能给出错误的结构化需求值；本模块未做全套输出内容审核 |
| 天气异常污染状态或行程 | provider接收请求副本；检查状态、连续日期、行程范围与降雨概率；失败时不保留旧daily，捕获异常后仅显示异常类型 | 这是返回结构校验，不证明天气预报准确；已返回的summary/source并没有额外的全面脱敏过滤 |
| 工具失败或缺密钥阻断演示 | 无密钥用本地提取；模型最多2次尝试，单次HTTP超时20秒；天气异常转error并保留可用请求 | 本地规则覆盖有限；“调用完成”可能是回退成功，应通过extraction_status与trace区分真实模型成功 |
| 费用错误被显示为预算通过 | 检查非负整数分项及求和一致性；无法验证时明确unverified | 样例单价不等于实时行情，算术一致也不代表费用范围完整 |

工具边界会复制请求及天气日数据，防止provider直接改写下一轮的规范状态。真实预报与用户指定雨天分开标注；提醒仅生成人工待办，不会自动预订、付款或推送。

## 交接与限制

依赖接口：find_city(city)返回城市数据副本或None；build_chengdu_plan(request, weather)及build_city_plan(request, weather, city_data)均返回itinerary, budget_items, total_cost, changes, warnings；fetch_weather(request)返回共享WeatherContext。A的独立交付集合与完整仓库有区别，运行时需项目具有对应目录、规则和天气模块。

本地提取和模型字段提及检查覆盖固定演示与常见表达，不是所有中文语义的完整证明；相对日期、复杂否定/指代、预算区间与每人预算等尚有限制。模型虽受校验仍可能出现语义错误，真实模型需独立实测。报价为教学估算；不执行真实预订、付款、系统推送或报销审批。
