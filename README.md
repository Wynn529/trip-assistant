# 行知 · 旅行规划助理

课程项目：旅行规划与执行智能体。用户用一句话描述出行需求，智能体提取需求、查询天气、按样例数据和规则生成行程与预算，并提供提醒清单、本地保存和两类 CSV 导出。

## 1. 项目能力与教学边界

**能做什么**

- 多轮对话：每轮在上一轮条件基础上修改，例如“去成都三天，预算3000元，带一位老人”→“第二天下雨”→“预算降到2500元”。
- 已收录 6 个城市的样例数据：成都、北京、上海、广州、西安、重庆。可生成逐日行程和分项预算（住宿、餐饮、市内交通、景点门票、机动费用）。
- 雨天把户外景点换成室内景点；有老人时避开不适合老人的景点；“少走路”时每天只安排一个主要地点。
- 超预算时依次改用经济型住宿、把收费景点换成更便宜的；仍不够时提示该天数和人数下的最低估算。
- 可选：联网查询 Open-Meteo 逐日天气（16 天内），降水概率较高的日子自动按雨天安排。
- 可选：接入 DeepSeek。**Agent 模式**下由模型自主决定调用哪些工具（修改需求、查城市、查天气、规划行程），观察结果后决定是否调整并重新规划，最后用自然语言回复并追问缺失信息；价格和天气仍由工具计算。失败或未配置密钥时自动回退到固定流程和本地规则。
- 预订待办与应用内到期提醒、模拟费用记账、行程 CSV 和费用 CSV 导出、本地保存与载入。

**教学边界（不做什么）**

- 所有价格都是**教学估算，未核实**，不是实时报价；预算**不含往返目的地的大交通**。
- 未收录的城市（例如杭州）只给出方向性建议，预算显示为“未核实”，不显示总价。
- 不执行真实预订或付款；提醒只在应用打开时显示，不发送系统推送；费用记账是模拟账本，不做发票识别或报销审批。

## 4. 无 Key 四轮演示

不需要任何配置。保持左侧“使用 DeepSeek API”和“查询实时天气”关闭，按顺序点击左侧“一键演示”：

| 顺序 | 按钮输入 | 应观察到 |
|---|---|---|
| 1 | 去成都三天，预算3000元，带一位老人 | 成都 3 天行程、分项预算、“教学估算在预算内” |
| 2 | 第二天下雨，改成室内行程 | 第 2 天换成室内景点，标“雨天调整 · 用户模拟”，调整说明列出替换 |
| 3 | 预算降到2500元 | 改用经济型住宿，预算显示 ¥2,500 |
| 4 | 尽量少走路 | 每天只保留一个主要地点（优先时长短的），调整说明列出去掉的景点，总价随门票减少 |
| 5 | 去杭州三天，预算3000元 | 未收录城市：提示缺少可核实报价，不显示总价和预算差额 |

想从头开始，点“清空当前对话”。

## 5. 有 Key 配置

1. 复制 `.env.example` 为 `.env`，放在项目根目录，填写 `DEEPSEEK_API_KEY`。`.env` 已被 `.gitignore` 排除，不要提交，也不要截图。
2. 可选变量：`DEEPSEEK_MODEL`（默认 `deepseek-flash`）、`DEEPSEEK_BASE_URL`（默认 `https://api.deepseek.com`）。
3. 重启页面后，“使用 DeepSeek API”开关可用。
4. 判断是否真实调用成功：看“执行轨迹”第 1 行。显示 `DeepSeek deepseek-flash 已提取需求` 才是模型调用成功；显示“两次调用失败……已回退本地提取”则是回退。
5. 左侧“Agent 模式：模型自主调用工具”默认开启：每一步调用了什么工具、得到什么结果，都记录在“执行轨迹”页签（“Agent 第N步”）。模型回复中如果出现工具结果之外的数字，会被丢弃并改用规则模板（轨迹中有“回复校验”）。关闭 Agent 模式时，模型只负责把话转成需求字段；行程、预算、天气均由本地数据和规则计算。模型修改了用户本轮未提到的字段时会被忽略（轨迹中提示“已忽略本轮未涉及字段”）。模型相对规则的主要优势是理解口语和相对日期，例如“带爸妈”“跟老婆带个娃”“后天出发”“国庆”。

注意：如果系统环境变量里已存在 `DEEPSEEK_API_KEY`，程序优先使用系统中的值，不读取 `.env`。

**真实调用检查**：`.\.venv\Scripts\python.exe -B agent_live_check.py --save`，连续三轮真实调用，并把结果保存到 `docs/evidence/agent-live-时间.json`（不含密钥）。

## 6. 天气开关与模拟雨天

- **“查询实时天气”默认关闭**，此时不联网，页面显示“未开启查询”；雨天只来自用户在对话中的说明（如“第二天下雨”），行程标“用户模拟”。
- 打开后，需要提供 16 天内的出发日期（对话中写 `2026-11-05出发`，或用“调整出发日期”）。成功时顶部显示“天气：已获取（Open-Meteo）”，每天卡片显示天气、气温和降水概率；降水概率较高的日子按雨天安排，标“实时预报”。
- 未获取时会写明原因：未提供出发日期、出发日期已过、超出可查询范围、暂不支持该城市、数据不完整、查询失败。

## 7. 保存位置和实际保存范围

- 点击“保存当前行程”，在项目根目录 `local_data/` 生成一个 JSON 文件（文件名为时间加随机后缀）。`local_data/` 已被 `.gitignore` 排除。
- **保存的内容**：当前这一份行程结果，包括需求条件、天气、逐日行程、预算分项与预算状态、调整说明与提示、预订待办、执行轨迹和智能体回复。
- **不保存的内容**：对话记录、模拟费用记录、待办勾选状态。
- “载入选中行程”恢复行程结果和需求条件，可在其基础上继续对话；对话框只追加一条“已载入”提示。

## 8. 两类 CSV 各自字段

两类文件均为 UTF-8（带 BOM，Excel 可直接打开）。

**行程表.csv**（“每日行程”页签 → 导出行程 CSV）

| 列名 | 说明 |
|---|---|
| 天数 | 第几天 |
| 日期 | 有出发日期且天气查询成功时才有值 |
| 景点 | 每个景点一行 |
| 费用估算/人 | 单人门票估算；未收录城市显示“未核实” |
| 雨天状态 | 实际写入雨天来源：“演示模拟”“实时预报”，非雨天为空 |
| 备注 | 当天安排说明 |

**模拟报销汇总.csv**（“模拟报销”页签 → 导出费用汇总 CSV）

| 列名 | 说明 |
|---|---|
| 日期、类别、金额、备注 | 用户录入的模拟费用 |
| 凭证状态 | 固定为“模拟记录，未上传真实凭证” |
| 最后一行 | “合计”，与页面“已录入费用”一致 |

## 9. 常见启动故障

| 现象 | 处理 |
|---|---|
| `streamlit` 不是内部或外部命令 | 用 `.\.venv\Scripts\python.exe -m streamlit run app.py`，不要直接敲 `streamlit` |
| `ModuleNotFoundError: travel_agent...` | 确认在项目根目录启动，且 `travel_agent/` 下有 `rules`、`data`、`tools`、`storage`、`ui` |
| 端口被占用 | 加参数换端口：`... -m streamlit run app.py --server.port 8502` |
| 文字和背景颜色太接近 | 项目已在 `.streamlit/config.toml` 固定浅色主题；也可在页面右上角菜单 Settings 中选 Light |
| DeepSeek 开关是灰色的 | 未检测到密钥，见第 5 节 |
| 执行轨迹显示 DeepSeek 调用失败（HTTPError） | 多为密钥无效或余额不足；检查是否被系统环境变量中的旧密钥覆盖 |
| 天气一直“未获取” | 打开天气开关；提供 16 天内的出发日期；确认网络可访问 open-meteo.com |
| 改了 `travel_agent` 下的代码没生效 | 停止并重新启动页面 |

## 10. 已知限制

- “少走路”通过减少每天的主要地点实现，没有计算实际步行距离。
- 价格为教学估算，酒店按每间每晚、门票按单人成人票估算；不含城际交通。
- 仅 6 个城市有样例数据；其他城市只有未核实的方向建议。
- 多轮对话会沿用上一轮条件：换城市时，之前说过的雨天、老人等条件仍然有效，需要时点“清空当前对话”。
- 雨天多、天数长时，室内备选可能用完，页面提示“室内备选不足，请人工核对”。
- 本地规则提取覆盖的说法有限；同一字段规则与模型都识别时以本地规则为准。模型修改的字段只有在本轮话里出现相关词（如“老人/爸妈”“小孩/娃”“明天/国庆”）时才采纳。
- 提醒只在应用打开时显示；到期日由出发日期推算（出发前 7 天），没有出发日期时不提醒。
- “执行轨迹”中的合同版本显示为 1.0（服务层未填写该字段）。
